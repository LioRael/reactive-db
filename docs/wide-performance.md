# reactive-db：多层宽图的分配热点与布局交叉验证

直接基线 `31964e3`。只修改 reactive-db 和任务验证目录，未修改 livequery、tanstack-db-rs。纯安全 Rust、零运行时依赖，公共 API 不变。

## 结论

**多层宽图的最终收益跨分配条件和角色方向成立。** 相对当前基线，正常角色的三个条件降低 10.7% / 11.6% / 10.6%，角色互换后降低 9.8% / 7.5% / 9.2%。各进程、创建顺序和计时顺序分组均为改善方向。独立版本 Criterion 两组成对变化为 **-2.5% / -15.6%**，方向也一致；绝对幅度随运行条件变化，不能承诺固定百分比。

旧的 1.6–3.3% 差异与本轮空对照的偏差量级重叠：空对照汇总约 -1.1% 至 +1.9%，单个进程/计时顺序分组可达几个百分点。因此不能追溯性地断言旧差异全部是真实退化或全部是噪声。本次消除的是源码与采样共同确认的临时分配成本，其 7.5–11.6% 的矩阵收益明显大于汇总空对照偏差。没有用不同历史实验的绝对时间计算与更早版本的收益。

保留收益场景没有跨方法一致的大幅回退：大 fanout 独立两组为 -1.4% / -1.0%；单层万节点密集传播在两种角色下约降低 12–13%。短路径和 join 汇合仍对实例/布局敏感：正常角色 join 汇合约 +6.1%，角色互换后 -1.3%，独立对照 -7.9% / +2.5%。剪枝独立对照 -12.1% / +12.2%，不应作为本次新增收益，也不能保证每次运行零回退。完整结果如下，不隐藏这些信号。

批量 filter/map 的 100 条变化两组约 +0.6% / +2.1%，1,000 条约 -1.4% / +0.1%。单条优化没有改变批量语义，但新增判断及布局可能产生小幅代价；不宣称所有规模全面变快。

## 定位证据与最终实现

对基线的两层宽图运行 release 工作负载，用 macOS `/usr/bin/sample` 以 1 ms 间隔采样 3 秒。主线程得到 2,267 个样本，调用树明确包含 `Runtime::prepare → Linear::prepare → malloc/free`，另有阶段提交/释放和调度成本。采样用于定位，不能将内联/去重符号中的栈样本直接当作精确的函数独占占比。

源码与采样相符：源集合的单行发布上一轮已优化，但每个 filter/map 节点仍先向 Vec 放入一个 Change，再转为 Arc 切片。两层、每层 10,000 个 map 节点，且每节点产生一条变化时，每次写入会多构造 20,000 个这样的临时 Vec。

最终仅在现有 `Linear::prepare` 循环中新增分支：**单条输入且确实产生输出**时，在原位置完成 output 预算检查，然后直接构造单条共享 delta。单条无输出的过滤、空输入、多条输入继续沿原循环执行。输入 ID 仍按原规则克隆，因为它借自上游 delta；没有改成引用跨越提交边界。

构造放在私有 `single_pending` 函数中，并使用 `#[inline(never)]`。这是有对照数据支持的选择：最初独立单条准备分支重复了求值逻辑；改为循环内分支后，内联构造版本的剪枝短对照仍退化。独立构造函数限制准备函数中的新增代码体积，短对照同时保留宽图收益与剪枝表现。未使用填充指令、特殊哈希 seed、布局阈值或持久缓存来追逐某次结果。**没有证明寄存器压力是唯一原因**，不同二进制布局的影响仍需通过角色互换和独立进程观测。

结果仍是同一种 `Arc<[Change]>`，共享、发布、订阅和释放语义不变。工作与输出计数仍在相同位置累计；prepare→commit 原子边界、empty-delta 剪枝、退休回收均未修改。先前的源单行路径、稀疏调度、紧凑宽图队列、大 fanout 借用候选、稳定去重和 join 单行索引补丁全部保留。

## 区分分配成本与测量偏差

环境：Apple M2 Pro、16 GiB、macOS 27.0.1、Rust 1.99.0 release。基线的两份 src 在添加测试前逐文件核对 `31964e3`，26 文件一致。没有与本任务的构建/测试并行计时；没有锁定 CPU 频率或屏蔽系统其他后台活动。

宽图测试有三种分配条件，每次创建一对数据库前执行：

- `fresh`：直接重建，不做额外堆扰动；**不是重置系统分配器**。
- `churn`：分配并释放 4,096 个缓冲，大小轮换 32/48/64/128/256/1024 字节，总 payload 约 1 MiB，再创建图。
- `held`：创建同样的缓冲，但保持到这一对实例计时结束后才释放。

这测试了堆历史和存活分配对结果的敏感性，未更换 macOS 分配器，也不能穷尽所有分配器行为。

正常角色运行 3 个独立进程；每场景/分配条件/suite 重建 4 对实例，每对校准、预热后计时 4 对约 50 ms 窗口。创建、校准、计时先后交叉。宽图同时有 old_null（基线自身）、new_null（候选自身）和 paired（基线/候选）；其他保留收益场景跑 paired。

再交换两个 crate 依赖别名，运行 3 个新进程，以相同分配条件和实例协议复核 paired。反向数据归一化后，A 总是基线、B 总是候选；原始反向 CSV 的角色标签没有改写。正常 672 对窗口、反向 384 对，总计 **1,056 对窗口**，对应 **264 对重建实例**。每个分配条件/角色下的 paired 结果来自 12 对实例、3 个进程。相同实例的重复窗口不当作独立实例，跨进程也只有 3 个簇/角色，不作过度置信声明。

表中先对每个实例的 4 个配对比取中位数，再汇总实例。耗时是窗口平均 ns/op 经两级中位数聚合，变化率单独按配对计算；不能用两列独立汇总耗时直接相除。null 表中 A/B 是同一实现的两个实例，不是两个版本。

还使用基线、候选各自独立编译的 Criterion 可执行文件，两组成对 A→B / B→A，反转场景顺序；40 样本、1 秒预热、3 秒 measurement。包括两个批量 filter/map 场景，防止单条快速分支拖慢多条输入。两侧先构建再计时；表中范围为运行中位数范围，原始 median/mean 与 95% CI 另存 CSV/JSON。

## 回归与资源语义

新增两项回归，共 **105 项测试**（92 unit/integration、13 rustdoc，含 10 compile-fail）通过：

- 独立模型比较单条与多条输入的 filter/map：插入、删除、正负值转换、额外被过滤的更新，验证最终行、是否传播、工作/输出计数、transform 调用次数，以及准备阶段不修改已发布状态。
- 单条 map 在输出预算不足时拒绝，或成功准备后直接丢弃 pending，Weak 都证明新派生 payload 已释放；已发布状态保持不变。

这两项语义测试在基线上也通过。既有跨集合原子发布、宽图精确预算与失败重试、部分 stage 释放、独立全重算模型、自连接和退休回收测试继续通过。优化没有新增持久缓冲或容量高水位；多条输入仍用原来的 Vec，单条输出省去临时 Vec，**不是整个 write 零分配**。预算仍是逻辑工作/输入/输出计数，不是字节或墙钟限制。

标准 Cargo check/clippy（all-targets/all-features、-D warnings）、test、release test、fmt check、rustdoc（-D warnings）通过；Rust 1.88 check/test 通过。两个比较 harness 也单独通过 clippy。使用工具链绝对路径并清空 RUSTC_WRAPPER/RUSTC_WORKSPACE_WRAPPER，未经过 Blaze，未更改全局配置。

内存 benchmark 连续 10 轮、每轮 10,000 行、每 payload 256 字节；database 与外部 snapshot 释放后每轮 live payload 为 0。RSS 约 30.4–31.6 MiB，分配器可保留页，不能将 RSS 当作活对象数量或所有场景无泄漏的证明。

## 复现与数据

`benchmarks/wide.rs` 是独立纯 Rust 比较 harness，不加入产品依赖或默认 Cargo targets。创建比较工程，复制为 `src/main.rs`；导出基线 `31964e3` 的 src 到 `before/src`，为该副本设置 package 名 `reactive-db-baseline`、version `0.1.0`、edition `2024`、rust-version `1.88`，无依赖。比较工程依赖：

```toml
[package]
name = "wide-benchmark"
version = "0.1.0"
edition = "2024"
[dependencies]
old_db = { package = "reactive-db-baseline", path = "before" }
new_db = { package = "reactive-db", path = "/path/to/reactive-db" }
```

先 release 构建，再分别设置 `BENCH_RUN=0`、`1`、`2` 串行启动，保存各自 CSV。交换两个依赖别名后设置 `ROLE_REVERSED=1`；主 harness 默认只跑宽图，交付的反向 harness 还复测全部守护场景。原始反向 CSV 中 before 是候选，实例汇总 CSV/JSON 已归一化。`PROFILE_BASELINE=1` 运行基线宽图 8 秒并输出 ready 标记；在预构建的进程上单独执行 sample，不与正式计时并行。

独立 Criterion 命令示例：

```sh
cargo bench --bench scheduler --locked --offline -- 'scheduler/layered/10000$' --noplot --sample-size 40 --warm-up-time 1 --measurement-time 3 --save-baseline before
cargo bench --bench core --locked --offline -- 'window_and_delta/filter_batch/1000$' --noplot --sample-size 40 --warm-up-time 1 --measurement-time 3 --save-baseline before
```

正式数据为 1,056 对实例窗口和 28 组独立 Criterion estimates。交付同时保存采样原文、最终窗口/实例汇总、独立 median/mean/CI、内存与验证日志，以及未采用候选的短对照，便于核查选择过程。

实际验证使用显式 Rust 1.99.0 工具链路径并清空两个 wrapper；为绕过本机 rust-objcopy/LLVM 兼容问题，两侧统一设置调用级 `CARGO_PROFILE_BENCH_STRIP=none` 和 `CARGO_PROFILE_RELEASE_STRIP=none`。没有修改全局或项目 Cargo 配置、没有更换分配器。后续如继续追求几个百分点的差异，应继续保留空对照和角色互换，而不是以单次最优结果判断回归。
