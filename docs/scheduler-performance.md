## 实现结论

已移除写入路径中的三次全图工作：存活检查、prepare 遍历和 commit 遍历。

- 物化成功后按父节点先于子节点的顺序分配单调 rank，维护反向依赖。容量溢出在注册之前拒绝；失败物化不会留下半条依赖。
- 全部源 delta 先暂存，再由非空 delta 的源触发后继。按 rank 排序并去重的 ready 集保证不同深度的汇合路径、同批次双边 join 和自连接在输入齐备后仅求值一次。
- 节点不输出 delta 时停止传播；join/group/ordered 的内部维护仍加入提交列表。因此不会丢失以后匹配、撤回或窗口更新需要的索引状态。
- commit 列表为稀疏 Vec：源先提交，派生节点按求值顺序提交，无需再次扫描或排序全部节点。所有普通错误和预算检查均发生在发布之前，epoch 最后推进。用户代码 panic 仍遵循既有 fail-stop/poison 规则。
- 每条被遍历依赖边在入队前计入 work，每个到达节点在求值前计入 work。队列扩张也受预算约束；汇合的不同边分别收费，同一节点只求值一次。计数变化属于已文档化的诊断值变化。
- 最后一个已注册 plan token 释放时登记退休事件。下一次 create/materialize/write 排空事件并移除节点与反向边；先释放队列借用，再运行析构，可处理闭包释放另一查询导致的级联。未物化 token 不登记，运行时 Weak 保留地址避免 ID 复用；Database drop 同时释放待回收队列缓冲。

调度成本随到达节点 A 和遍历依赖边 E 增长，另有 BTree 查找、队列排序以及算子本身的成本。不能宣称严格 O(A)：全局节点/依赖查找仍含 log(V)，ready 集含 log(A)。持久调度元数据为 O(V+E)，暂存队列/提交列表随本批受影响部分增长。退休清理不纳入逻辑执行预算，也不承诺墙钟、字节或任意用户闭包时间上限。

关键代码：`src/database.rs:224`（稀疏调度和发布）、`:272`（退休事件排空），`src/scheduler.rs:26`（注册）、`:45`（入队预算）、`:58`（移除边），`src/engine.rs:44`（生命周期 token）。API 保持不变。

## 验证

新增 9 个测试：6 个面向行为的集成回归、3 个生命周期/rank 边界单元测试。总计 78 个测试通过（65 unit/integration，13 rustdoc，其中 10 个 compile-fail）。保留三组独立全重算模型的 18,800 个生成批次；这些模型不复用增量执行器实现。

覆盖无关节点数 0/100/1,000/10,000 下相同写入 work、小预算下空 delta 剪枝、group/distinct 撤回缓存、不同深度的 join 输入、双源同批次更新、自连接一次求值、订阅统一 epoch、入队预算耗尽后的无发布与重试、失败物化重试、订阅持有、析构级联释放及反复 churn 后无残留边。既有模型/合同测试继续覆盖 left join、join key 变化、空输出 join 索引维护、排序和 top-k 窗口维护、失败预算下各算子回滚。

同一集成测试文件在改前基线上运行，6 项中 4 项失败：无关图宽度耗尽预算、空输出未剪枝、fanout 未在求值前受预算约束，以及一次退休清理未完全处理析构级联。后两项的细节：旧实现预算失败仍保持数据原子性，但会在失败前调用一部分投影；旧退休扫描是否漏掉级联与节点地址遍历次序有关。本次基线运行明确复现了这两项，不能据此称旧版本每次都漏清理。

标准 native Cargo 验证：fmt --check、check --all-targets --all-features、clippy --all-targets --all-features -- -D warnings、test、doc --no-deps（rustdoc warnings as errors）；Rust 1.88 的 check/test；另有 release test。全部成功。显式使用安装的 cargo/rustc/rustdoc，并以调用级空 RUSTC_WRAPPER/RUSTC_WORKSPACE_WRAPPER 绕开 Blaze；没有修改全局配置。性能/release 调用仅覆盖 strip=none，以避开本机 rust-objcopy 的 LLVM 动态库问题。运行时 cargo tree 只有本 crate，Criterion 是 dev-only。

## 内存释放

`cargo bench --bench memory --locked` 的 10 轮运行，每轮构建 10,000 源行和 10,000 映射行（各 256 字节 payload），物化 join/group/distinct/top-k，再按既有外部 snapshot 契约释放。每轮最终 live payload 均为 0；drop 后 RSS 为 30,240–31,424 KiB。RSS 含分配器缓存，短期稳定范围不等同于长期泄漏证明。新增回归额外验证订阅保留、运行时闭包触发的级联退休，以及数据库销毁后幸存句柄不保留退休队列容量。

此更改只保证执行器自身拥有的引用按租约释放；调用者保留的 snapshot、payload 和任意用户自建引用环不受本库回收控制。
